# План исправлений после ревью MBO

Главное правило: исправления не должны ухудшать игровую логику, внешний вид, плавность платформ или совместимость существующих сохранений. Галочка ставится только после успешной компиляции.

## Критические

- [x] При сбросе платформа могла удалить весь объём вместе с посторонними блоками.
- [x] При материализации платформа могла перезаписать блоки, поставленные в точке назначения во время движения.
- [x] Сервер чрезмерно доверял координатам лодки из клиентского пакета.
- [x] Клиентский sync-NBT запираемых блоков раскрывал комбинацию замка и скрытые данные.

## Высокий приоритет

- [x] Коллизии каждой платформы каждый тик перебирали все загруженные сущности мира.
- [x] Таблица пассажиров платформ сохраняла устаревшие UUID игроков и ссылки на удалённые платформы.
- [ ] Сетевые обработчики изменяют игровой мир вне основного потока.
- [x] Удалённая настройка и восстановление LootContainer не проверяли расстояние до блока.

## Надёжность и сопровождение

- [x] Повреждённый UUID платформы или станции мог сорвать загрузку сущности/чанка.
- [x] Spawn-NBT платформы выделял массив до проверки допустимого размера.
- [x] Входящая конфигурация LootContainer не ограничивала опасные размеры, строки и числовые значения.
- [x] Цветовой префикс ошибок LootContainer записан независимо от кодировки исходника.
- [x] Удалить лишние релизные отладочные сообщения или перевести их на нормальный логгер.
- [x] Логировать ошибку загрузки современного шрифта один раз, без спама.
- [x] Зафиксировать версию ForgeGradle вместо динамической `1.1.+`.
- [ ] Добавить минимальные автоматические тесты сериализации и валидации критичных данных, если старый ForgeGradle позволяет запускать их стабильно.

## Порядок дальнейшей работы

1. Безопасная обработка сетевых пакетов в основном потоке.
2. Диагностика и воспроизводимость сборки.
3. Минимальные регрессионные тесты.
